# Daily Update — August 7, 2026

*Written for non-technical stakeholders. Plain language, no jargon.*

## In one line

Status changes and notes have not been reaching Monday.com for anyone who
connected their Monday account before August 4th — the dashboard showed them as
saved and then quietly reverted them. Found today, fixed today.

---

## What was actually happening

When you change a status here, the dashboard sends that change to Monday under
**your** Monday account, so the change is attributed to you rather than to a
faceless service account. That connection is made once, from Settings.

Monday grants that connection a fixed set of permissions **at the moment you
connect it**, and never widens them afterwards. Permission to edit a field was
added to our connection screen on **August 4th**. So every account connected
before that date was allowed to post notes and nothing else — and one connected
on June 30th, during a short window, could not even do that.

Three things then combined to hide it:

1. The dashboard applied your change locally straight away, so on screen it
   looked like it had worked.
2. When Monday refused the change, the system filed it for a retry — and every
   retry used the same connection Monday had just refused. After five attempts
   it gave up.
3. A while later the routine refresh pulled Monday's real value back over yours,
   so the status simply appeared to change back on its own.

Nothing announced a failure at any point. The admin screen reported a number of
stuck changes but not the reason, which is why the pattern was not obvious
sooner.

---

## The fix

- **Changes now go through even from an out-of-date connection.** If Monday
  refuses your personal connection, the change is made under the firm's shared
  account instead. You lose your name on that one change; you do not lose the
  change. That tradeoff is deliberate.
- **You get told.** An out-of-date connection now turns the Monday panel in
  Settings amber and says so. Reconnecting is one click and puts your name back
  on future changes.
- **The retry queue stopped being pointless.** It now falls back the same way,
  instead of spending five attempts on a connection that cannot work.
- **Admins can see the reason.** Sync Health lists recent failed write-backs
  with Monday's own error message, not just a count.

A dead duplicate entry was also removed from the server configuration file. It
was harmless where it sat, but had it been read in the other order it would have
broken *every* write for everyone, not just the ones described here.

---

## What this does not fix

**Changes lost over the past days are gone and need to be redone.** They were
never applied in Monday, and replaying them now would be worse than not: they
would overwrite whatever has been set in Monday since. Anyone who changed a
status and later found it back to its old value should assume the change did not
take.

The window depends on the account:

- Connected on **June 30th** — notes and status changes both affected.
- Connected between **July 1st and August 4th** — status and field changes
  affected; notes were fine.
- Connected on or after **August 4th** — unaffected.

---

## Where things stand tonight

- **Ready, awaiting deploy:** everything described above, plus yesterday's four
  fixes, which have not gone out yet either.
- **After that deploy:** anyone whose Settings panel shows amber should
  reconnect Monday once.
- **Still pending from yesterday:** Monday has to be re-registered to notify us
  about deleted notes, otherwise that fix sits idle.

---

## Closing note

The uncomfortable part of today is not the bug — it is that the system reported
success while doing nothing, for days, and the one screen built to show trouble
showed a number without a reason. The fix restores the writes; the more useful
change is that a refusal is now visible to the person it affects, at the moment
it affects them.
