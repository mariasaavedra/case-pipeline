# Daily Update — August 25, 2026

*Written for non-technical stakeholders. Plain language, no jargon.*

## In one line

The Call Log board now has a fast, one-popup way to log a call and link it to a
client — replacing a process so friction-heavy that, checked against your real
data, only about **1.5% of calls** were ever getting linked to a client. It's
built, tested, deployed, and verified working against production.

---

## The problem, in your own numbers

Before writing any code, the board was checked against what's actually in it
today: roughly 5,000 recent calls, and only 75 of them linked to a client
profile. Staff clearly weren't skipping the link out of carelessness — the old
path (open Monday, create an item, type the note as its name, then separately
search for and link the client) was just too many steps for a phone that's
still ringing.

---

## What was built

**A "+ Log call" button, visible everywhere in the dashboard.** Click it, and:

- Type the caller's phone number — it searches your existing clients as you
  type.
- Pick a match and their name and phone fill in automatically.
- Type a quick note.
- Submit. Done.

**A new Call Log tab**, showing the board as a filterable list — by status, by
staff member, or "unlinked to a client" for a daily follow-up sweep — with the
same status editor already used elsewhere in the dashboard.

Everything writes straight to the real Call Log board in Monday.com, under the
same safety net every other write in this dashboard already has: if Monday is
briefly unreachable, the entry is saved locally and retried automatically
rather than lost.

---

## The note goes three places, not one

Partway through, the request was refined: a call's note shouldn't just sit on
the Call Log entry — if the call is linked to a client, it should also show up
on **that client's own record** in Monday, two different ways:

1. As a comment on the Call Log entry itself (so the call has its own record).
2. As a comment directly on the **client's profile** in Monday — so the client's
   own update history reflects it, not just our dashboard's.
3. As a new **"Call Summary" activity** on the client's profile — the same kind
   of entry as a Consult Note or Contract Note, so it shows up in the client's
   full activity history in Monday.

That third one needed an honest check first: the "Call Summary" option staff
already see in Monday's own compose menu turned out to be a built-in preset
with no way to create it through Monday's API — confirmed directly against
Monday's systems rather than assumed. The fix was to create a new activity
type with that same name. The tradeoff — staff will see two things labeled
"Call Summary" in Monday's menu, the original and this new one — was surfaced
and approved before doing it.

---

## Two things your own testing caught

Testing this for real surfaced two problems that automated checks alone
wouldn't have:

- **The caller's name and the note got swapped.** The first version used the
  note as the item's name in Monday, matching how staff already did it by
  hand — but that's not what was wanted. Fixed: there's now a proper "name"
  field, and the note is only ever a comment.
- **The phone number sometimes logged wrong.** Picking a client from the
  search results didn't overwrite whatever partial number was still sitting in
  the phone field from typing — so a call could get logged with "816-605"
  instead of the real number. Fixed: selecting a client now fills in their
  actual phone number on file.

Both were confirmed against real entries already sitting in your Monday board
before being called fixed, not just assumed fixed.

---

## A bug this work exposed, fixed rather than shipped

Building this surfaced a real gap in how the dashboard retries a failed write
during a Monday.com outage: if creating a new item failed and was queued for
retry, a successful retry later would forget the new item's own ID — which
would have caused that item to show up **twice** on the next daily sync. This
already existed for every other feature that creates new Monday items; it just
hadn't been exercised yet. Fixed and covered by tests before shipping.

---

## Deployed and verified

This is live in production, not just tested locally:

- The images built and deployed cleanly.
- The production database needed its own one-time catch-up sync for the
  newly-tracked board — that's done. **69 real, current calls** are now
  visible in the live Call Log tab, confirmed directly against the server.

## What's next

- The board holds more than 5,000 historical calls; only the most recent 5,000
  were pulled in this pass. Backfilling the rest is a small config change
  whenever the full history is wanted.
- Deferred on purpose: creating a **brand-new** client profile from inside the
  popup when no match is found. Every other way a profile gets created today
  goes through Monday or Calendly directly, and building that safely deserves
  its own pass rather than being squeezed into this one.
