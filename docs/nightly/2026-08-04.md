# Daily Update — August 4, 2026

*Written for non-technical stakeholders. Plain language, no jargon.*

## In one line

Two big capabilities are built and shipped: **editing case fields directly from
the dashboard** and **creating contracts from a client's page** — both write
straight into Monday.com. They light up after one deploy + a data refresh.

---

## What we shipped

### 1. Edit any field on a case, in place (Active Cases)

Every item under **Active Cases** — Open Forms, RFEs, Changes of Address,
I-918Bs, and the rest — now **expands with a click** to show its editable fields.
You can change a **status, date, amount, or text** right there, and it writes
straight to Monday.com under your account.

- Status/dropdown choices are limited to that board's **real labels**, shown in
  Monday's **actual colors** — you can't set something that doesn't exist.
- Calculated and mirrored fields (and profile look-ups) are left out on purpose —
  only what you can actually change is shown.

### 2. Create a contract from the client's page (Contracts tab)

A **"+ New contract"** button opens a short form: pick the **case type** and enter
**Attorney's fees, Filing fees, and Postage**. It creates the Fee K in Monday,
named **"Client — Case type,"** automatically linked back to the client's profile
(and their Open Forms entries when there are any).

- **Surcharges are intentionally left out here** — as you noted, the credit-card
  3% is only known *after* the client signs, so that becomes its own small step on
  the signed contract (planned next).

### 3. A version stamp + changelog

Every page now shows which build is running (click it for a plain-language
"what's new"). This exists because of the saga below — now we can always tell, at
a glance, exactly what's deployed.

---

## The hard-won fix behind all of this

Getting the first write-back (status editing) to actually work took an unusual
amount of digging — and, importantly, **none of it was the database.** Three
separate gremlins stacked up:

1. The build system was quietly shipping **old code stamped with the new
   version** (a caching bug), so fix after fix never reached the browser.
2. **One critical line never made it into a commit** (a filename capitalization
   quirk on Mac), so the piece that loads the editable options was missing in
   production while working perfectly on the dev machine.
3. Monday.com hadn't granted the app **write permission** for statuses — so writes
   were rejected until the permission was added and the account reconnected.

All three are fixed, and we added tooling (the version stamp, direct build
checks) so this class of confusion can't eat days again.

---

## To turn it on

- **Deploy**, then run **one data refresh** — that loads the field definitions the
  editors need. After that, expanding a case shows its fields instantly (it reads
  local data, never a live Monday call, so it's fast).
- **Heads-up:** creating a contract makes a **real** item in Monday — test with one
  you're happy to delete.

## What's next

- **Surcharges (2b):** on a signed contract, a subtle "Paying with credit card?"
  toggle that adds 3% to the total.
- **Freshness improvements:** so the field definitions load on startup (no manual
  refresh step), and detail views can pull a single item live from Monday when you
  need it dead-current — keeping the fast local cache for everything else.

---

## Closing note

The dashboard is no longer read-only. You can triage *and act* in the same place —
change a status, set a date, log fees, open a contract — without bouncing to
Monday. The plumbing under it (durable retry queue, per-user attribution, audit
trail) means every change is attributed, retried on a hiccup, and logged.
