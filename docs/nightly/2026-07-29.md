## The four things you reported

You raised four issues with the client timeline. Here's where each landed after
today's investigation.

### 1. Notes appearing up to 4 times — **fixed** 🐛

**What happened.** When we rebuilt the refresh to update in place (instead of
wiping and rebuilding every night), one piece was missed: Monday.com *notes and
replies* were being *added* on every full refresh instead of *matched* to what
was already there. So after a few nightly refreshes, the same note piled up two,
three, four times. (Emails and activities were never affected — they already had
a duplicate-guard; only Monday notes/replies lacked one.)

**The fix.** Two parts:
- **A one-time cleanup** that collapses each repeated note back to a single copy,
  keeping the original. It runs automatically on the next deploy, right after a
  fresh safety backup.
- **A permanent guard** so a note can physically only exist once per client from
  now on — future refreshes can't recreate the pile-up.

**Confirmed safe.** We ran the cleanup against a copy of the real database: it
kept every genuine note, removed only true duplicates, and passed its integrity
check. On our local copy there was nothing to clean (it predates the duplicating
refreshes) — which is exactly the proof that the cleanup never touches legitimate
notes. On the server, where the duplicates actually accumulated, it will collapse
them on deploy.

### 2. Filtering the timeline / emails-only — **already there** ✅

The timeline already has filter buttons: **All · Notes · Emails · Activities ·
Documents · Notices · Appointments**. "Emails only" works today. It wasn't
obvious because it was being undermined by problem #3 below — once that's fixed,
the filters do their job properly.

### 3. Activities showing only partially — **fixed** 🐛

**What happened.** The client screen loaded only the 50 most recent timeline
entries and then filtered them in the browser. For an active client, those 50 are
almost all emails — so clicking "Activities" showed only the handful of activities
that happened to fall inside that recent window. The rest were in the database the
whole time; the screen just never asked for them.

**The fix.** Filtering now happens on the server, per category. When you click
"Activities," the server returns *that client's activities* — complete — instead
of "the newest 50, then filtered." Same for Emails, Notes, Documents, and so on.
(The busiest single client has 382 timeline entries total, so every category now
comes back in full.)

### 4. Attachments / links on notes — **scoped as next feature** ✨

Today the system doesn't capture file attachments at all — it only pulls the text
of each note, so attached files are invisible (links that appear are just text
inside the note). Supporting real attachments means asking Monday.com for the
files, storing them, showing them as links/thumbnails, and re-importing the
email/activity history once. It's a genuine feature, not a quick fix — planned as
the next step.

## Closing note

Two of the four turned out to be real regressions hiding in the timeline, one was
already solved, and one is a fresh feature. The duplicate pile-up was a
side-effect of the very change that made refreshes safe (updating in place instead
of wiping) — now closed with both a cleanup and a permanent guard. And the
"missing activities" mystery was never missing data: the screen simply wasn't
asking for the whole picture. It is now.
