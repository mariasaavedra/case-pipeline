# Daily Update — August 6, 2026

*Written for non-technical stakeholders. Plain language, no jargon.*

## In one line

The dashboard now reflects Monday.com changes in **about a minute** instead of up
to two hours — Monday tells us the moment something changes, rather than us
checking on a timer — and four smaller problems found during testing were fixed.

---

## The dashboard stopped waiting

Until today the system refreshed on a schedule: every two hours during the day,
plus a full sweep overnight. That meant a status you changed in Monday at 9:05
might not appear here until 11:00. Worse, an item **deleted** in Monday stayed
visible until the overnight sweep found it.

Monday now notifies us the instant something happens, and the dashboard catches
up within about a minute:

- **Any field change** — status, date, person, amount — appears in roughly a
  minute.
- **Deleted items disappear right away** instead of lingering all day. They're
  still archived first, so nothing is lost and anything can be restored.
- **New notes show up almost immediately**, and editing a note in Monday now
  updates the text here too.

The scheduled refreshes stay switched on underneath. Notifications can be missed
or delayed on Monday's side, so the two-hourly refresh and the overnight sweep
remain the safety net. This makes the dashboard *faster*, and it does not become
a single point of failure.

It has been running on real activity since this afternoon: **242 changes arrived
and all 242 were applied**, with no failures.

---

## Four problems found and fixed

Testing during the day turned up four things worth naming, because two of them
were affecting daily use.

- **"Unauthorized" when refreshing a page.** Reloading a client's page often
  showed an authorization error. The cause: the page started asking for data
  before your sign-in session had finished loading, so those requests went out
  without credentials. They now wait the extra moment.
- **A note deleted in Monday stayed here.** The reason turned out to be simpler
  than expected — we had never asked Monday to tell us about deleted notes. Now
  we do, and the note (with any replies under it) is removed.
- **Two "Monday" buttons on the client page.** One was a working link; the other
  was permanently greyed out and labelled "Coming soon" — and its icon promised
  exactly what the working link beside it already did. Removed.
- **The "what's new" list was stuck on July 30.** That list is written by hand
  and hadn't been updated in three releases. Entries for August 4th, 5th and 6th
  have been added, so the version badge now tells you what actually changed.

## An honest note about today's delays

GitHub — the service that packages our updates for the server — had a **major
outage** for most of the afternoon. Builds sat in a queue and were cancelled
before they could start, several times over.

Nothing was lost and the dashboard was never affected: it kept running normally
throughout. The cost was time. We deliberately did **not** work around it by
building the update on a laptop and pushing that to the server — an untested
package going to a live system, with the automated test suite also down, is the
kind of shortcut that creates a worse problem tomorrow morning. We waited, and
the near-real-time work went live once the service recovered.
