# Daily Update — August 26, 2026

*Written for non-technical stakeholders. Plain language, no jargon.*

## In one line

The Call Log tab got several requested upgrades today — it now opens straight
to today's calls, lets staff fix a call after logging it, shows and lets you
add notes, and tags a coworker directly. Partway through real use this
afternoon, a bug from this morning's deploy was caught, traced, fixed, and
verified against production the same day — it had been silently keeping
notes off of Monday.com for about an hour and a half.

---

## What was built

- **Opens to today's calls by default**, with a day picker and a "show all
  days" option for going back further — previously it showed every call ever
  logged, oldest mixed in with newest.
- **Fix a call after the fact.** Wrong name, wrong number, or the wrong
  client got linked — there's now an edit option instead of having to fix it
  by hand in Monday.
- **"Highlighted For" is now visible and editable** right in the list, not
  just something set once at creation.
- **Columns can be resized** by dragging, so a long status label isn't cut
  off anymore.
- **Notes are now visible in the dashboard**, reading directly from the real
  conversation on the Monday.com item — including notes from calls logged
  before today, not just new ones.
- **Tag a coworker in a note** by typing `@` and picking them from a list —
  they get notified on the real Monday.com comment, same as if you'd typed
  their name over there directly.

## A bug from this morning's deploy, caught this afternoon

Adding the "tag a coworker" feature required asking Monday.com to notify a
specific person on a comment. That capability was checked and confirmed to
exist before building it — but the check looked at Monday's newest rules,
not the older, specific version of those rules this app is pinned to on
every single request it makes. The two disagreed on this one feature, and
Monday rejected it outright.

The real damage: because that rejected request was written into the shared
code every comment in the app goes through, **every note posted anywhere in
the dashboard started silently failing** — not just ones with a coworker
tagged. A call would still log fine, with the right name, number, and
status; the note typed alongside it just never reached Monday.com.

This was caught the same afternoon by a staff member testing the feature,
who noticed calls were logging but their notes weren't showing up on the
board. Checked directly against the real Call Log board rather than assumed:
confirmed the pattern held for recent calls, traced it to the exact rejected
request, and reproduced the failure on a live test item to nail down the
precise cause before writing a fix.

**Fixed by splitting the request in two.** A plain note — the overwhelming
majority of them, and every single one before today — now goes out exactly
as it always has, untouched by any of this. Only a note that actually tags
someone uses the newer rules, and only for that one request. Verified
against the real board again afterward, both with and without a tag, before
calling it done. A new check was also added that specifically watches for
this class of mistake going forward, so it can't slip through unnoticed a
second time.

**If you typed a note on a call sometime this afternoon, roughly a
90-minute window between today's two deploys, it's worth a quick check that
the note actually made it to Monday.com** — the call and its status would be
correct either way, only the note itself might be missing.

## A second, unrelated bug found the same way

A call logged at 2:11pm Central was showing up timestamped 7:11pm — a
straight 5-hour jump. The server's clock doesn't know it's supposed to be on
Central time; it defaults to a neutral setting that has no relationship to
where the firm actually operates. Every call's date and time is now pinned
to Central time explicitly rather than trusting the server's own clock,
and confirmed against the exact reported case before shipping.

---

## Not a bug: one thing to know about connecting Monday.com accounts

A staff member trying to connect their personal Monday.com account hit an
error and, because writes fall back to a shared account when a personal one
isn't connected, their calls were showing up logged under someone else's
name. This looked at first like it could be a scopes/permissions problem in
the code — it wasn't. The Monday.com app itself simply hadn't been installed
for that account yet. Once installed, it connected normally.
